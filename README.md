# mogu — みんなで、おいしく。

アレルギーと食の好みを共有し、複数人でお店を選ぶハッカソン用デモ。架空の20店舗、各4メニュー、幹事1人・ゲスト3人を初期登録しています。

## 起動・検証

Node.js 22.12以上を使用してください。

```sh
npm install
npm run dev
npm test
npm run build
```

開発URL: `http://localhost:5173/Fujitsu_teamE_demo/`。ポートが使用中の場合は起動メッセージを確認してください。

## 技術・構成

React / TypeScript / Vite / Tailwind CSS / React Router / lucide-react / localStorage。バックエンド・認証・APIキーはありません。

- `src/pages`: ホーム・検索、グループ作成/管理/参加、店舗詳細、店舗登録/編集、決定画面
- `src/components`: プロフィールのステップ入力、カード、共通表示
- `src/data`: 共通アレルゲンID、スコア定数、店舗/参加者/サンプルOCRデータ
- `src/lib/matching.ts`: 副作用のないマッチングと店舗/メニュー情報の整合処理
- `src/lib/storage.ts`, `src/hooks/useStore.tsx`: 保存、初回データ、別タブ更新の反映
- `.github/workflows/pages.yml`: 自動テスト・ビルド・GitHub Pages公開

## 主な機能

- 個人・グループ検索、エリア/予算/ジャンル絞り込み
- 招待リンクのコピーとゲスト参加、参加者の追加・編集
- アレルギーによる厳格な除外、全除外理由の表示
- 好みの一致理由、参加者ごとの最適メニューと満足度
- 店舗全体/メニュー別アレルゲン、交差接触情報、架空口コミ・地図
- 6段階の店舗登録、レシート・メニュー表の画像アップロードと日本語OCR、候補の修正・確認、メニューへの明示的な食材設定
- 店舗情報の編集、検索への即時反映、お店の決定・選び直し
- ページ更新後の保持、初期データへのリセット、保存エラー/存在しないURLへの案内

## 判定ルール

エリア・予算 → 全員のアレルゲンを統合 → 店舗全体で使用あり/未確認なら除外 → 確認済みメニューの個人スコア → グループ集計、の順番です。未登録のアレルゲンは未確認です。メニューに該当食材がなくても店舗全体で使用していれば除外し、好みや点数で緩和しません。

初期50点、好きな食材+15（計+30まで）、苦手な食材-20（計-40まで）、好きなジャンル+15、苦手なジャンル-15。0〜100に制限し、個人ごとに最高点のメニューを選びます。同点は安いメニューを優先。グループは平均×0.7＋最低点×0.3です。定数は `src/data/constants.ts`。

食材不明は食材による加減点なし、メニューのアレルゲン未確認は推薦対象外です。確認済みメニューに含まれるアレルゲンは店舗全体でも使用ありへ更新し、未確認メニューに候補があれば店舗全体の不使用宣言を未確認に戻します。

## GitHub Pages

管理リポジトリ: https://github.com/MamoruKomo/Fujitsu_teamE_demo

公開URL: https://mamorukomo.github.io/Fujitsu_teamE_demo/

`main`へのpushでテスト・ビルド・公開します。リポジトリの **Settings → Pages → Source** は **GitHub Actions** を選択。初回設定後は通常のpushのみで更新できます。PRはテスト・ビルドのみ実行します。秘密情報や環境変数の登録は不要です。

GitHub PagesにはSPAのrewriteがないため、HashRouterを使用しています。招待URLは `…/Fujitsu_teamE_demo/#/join/{groupId}`。ページ再読み込み・直接アクセスで404になりません。画像・アセットもリポジトリのサブパスに対応します。

## デモ手順

1. ホームで初期グループの候補と除外理由を確認。
2. マイグループで招待URLをコピー。同じブラウザの別タブで開いて架空のゲストを登録。
3. 元のタブで人数の更新を確認し、条件を変えて検索。カードのお店に決定、または詳細から決定。
4. 店舗の方へ → 自動入力済みの基本情報 → レシートまたはメニュー表の画像 → 画像を読み取る → 文字と候補の修正・確認 → 店舗全体の使用状況 → メニュー → 登録。サンプルでは固定結果を表示します。メニュー画面からもメニュー表OCRへ戻れます。
5. 店舗詳細の編集で情報を変更し、次の検索で反映を確認。
6. フッターの「初期データにリセット」で初期状態へ戻す。

## 制限・注意

**実際の個人情報・医療情報を入力しないでください。** アレルギー判定は架空データに基づくデモであり、実際の安全性を保証しません。意図しない混入も含め、実際の利用時には必ず店舗へ確認してください。おすすめ度は好みの点数であり安全性の指標ではありません。

データはブラウザの保存領域だけに保存します。同じURL・同じブラウザプロファイルの別タブでは反映しますが、別端末・別ブラウザ・シークレットウィンドウ・ローカルと公開サイトの間では同期しません。保存領域を使えない場合はエラーを表示します。リセットはそのブラウザ内の変更を削除します。

アップロード画像はTesseract.js 7でブラウザ内OCR（日本語・英語）を実行します。初回はCDNからworker・WASM・言語データを取得するため通信が必要です。画像そのものを外部サーバーに送信・保存しません。鮮明なJPEG・PNG・WebP（8MB以内）に対応し、PDFは対象外です。OCRには誤認識があり、料理名や価格、食材・アレルゲン候補を必ず確認してください。候補は文字列の照合であり、原材料の完全な推定ではありません。原材料が不明なものや画像にない食材を不使用扱いにしません。サンプル選択時のみ固定結果を使います。メニュー表の再読み取りはメニュー候補を置き換え、確認状態を未確認に戻します。店舗基本情報と初期メニューはダミーで自動入力し、アレルゲンは未確認から開始します。予約・投票・決済・実際のナビゲーションはありません。

写真は料理のイメージです。口コミは架空で、アレルギー判定には使いません。デモの混同を避けるため検索エンジンへの登録は抑制しています。ハッカソン用途ではSearch Console・解析・問い合わせフォームは不要です。本サービス化する場合は店舗確認、プライバシーの扱い、端末間同期を改めて設計してください。ソースのバックアップと復元はGitHubのコミット履歴、ブラウザ内の復元は初期リセットで行います。

## 写真

無料の[Unsplash License](https://unsplash.com/license)の写真を使用。写真はローカル同梱で、外部の画像サービスへの依存はありません。写真ごとの出典・撮影者・画像情報は `public/images/credits.json`。公開前の確認: `npm test`、`npm run build`、スマホ画面、招待リンク直接アクセス、レシート/メニュー表OCR・登録と検索の連携。

更新機能: プロフィールのアレルギー・好き/苦手食材を検索して追加/解除できます（読み方・別名対応）。「マイグループ」で全グループを一覧表示し、「新しいグループ」で名前・ニックネームだけの作成ができます。幹事には個人プロフィールを引き継ぎ、作成後に編集できます。

言語切替: ヘッダーから日本語 / English / 简体中文 / 한국어を切り替えます。表示言語はブラウザに保存され、再読み込み後も維持されます。UI・注意文・食材・菜系・デモメニューを翻訳し、食材検索は各言語の名称に対応します。店舗名・グループ名・ニックネーム・入力中の値・OCR原文は書き換えません。中国語は簡体字です。価格はすべて日本円で、言語による通貨換算は行いません。OCRの認識言語は引き続き日本語・英語です。保存IDやアレルゲン判定は言語に依存しません。
